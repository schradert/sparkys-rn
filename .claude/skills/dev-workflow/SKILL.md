# Dev workflow (devenv + bun + Expo)

The toolchain lives in the **devenv** shell — bun, the Expo CLI, the Android
SDK/NDK, scanners and LSPs are all provided there. Run project commands inside
it (`direnv allow` once, or `devenv shell`); from outside use
`devenv shell -- bash -c '<cmd>'`.

## Two command namespaces

- **`bun run <name>`** — everyday JS tasks (package.json `scripts`):
  `dev`, `dev:preview`, `dev:prod`, `android`, `ios`, `typecheck`, `lint`,
  `lint:fix`, `format`, `format:check`, `check`, `check:fix`, `test`,
  `test:watch`, `test:coverage`, `docs`, `doctor`.
- **devenv scripts** — bare-name ops/release flows: `bootstrap`, `security`,
  `doctor`, `build-dev|preview|prod`, `build-dev-local`, `eas-update`.
  `devenv up` runs the Metro process. The shell prints this list on entry.

## Starting work

```bash
bootstrap            # install deps + generate typed-route types + expo-doctor
bun run dev          # Metro for the development variant (APP_VARIANT=development)
```

`experiments.typedRoutes` is **on**: route types in `.expo/types` /
`expo-env.d.ts` are generated by Metro. After changing routes (or on a fresh
checkout) run `bun run dev` (or `bootstrap`) once **before** trusting
`tsc --noEmit`, or you'll see spurious `Href`/route errors.

## Linting & formatting — the split

Two tools, no overlap (so nothing is reported twice):

- **Biome** (`biome.json`): formatting, import organization, general JS/TS lint
  (unused vars, array style, correctness/suspicious). `bun run check` /
  `check:fix`.
- **ESLint** (`eslint.config.js`): React / React Native / Expo semantics only
  (rules of hooks, import graph). `bun run lint` / `lint:fix`.

Rules Biome owns are turned **off** in ESLint, and vice-versa. When adding a
rule, pick the owner and disable it in the other tool. `react/no-unescaped-
entities` is off (irrelevant in RN `<Text>`); the React-Compiler hook rules
(`set-state-in-effect`, `refs`, `immutability`, `exhaustive-deps`) are errors;
`noExplicitAny` and `noNonNullAssertion` are Biome errors (the codebase has zero
`any`).

## Types & tests

- `bun run typecheck` → `tsc --noEmit` (TypeScript ~6, strict).
- `bun run test` (jest-expo preset) / `test:watch` / `test:coverage`. Tests go
  in `__tests__/` beside the code as `*.test.ts(x)`. Coverage thresholds in
  `jest.config.js` are a ratchet — raise, don't lower.

## Editors (VS Code / Zed / Helix)

Launch the editor from **inside the devenv shell** so its language servers
resolve from the toolchain (`node_modules/.bin`, `nixd`). Config is provided for
all three: `.vscode/` (committed) plus `.zed/settings.json` and
`.helix/languages.toml` (both devenv-generated + git-ignored). TypeScript uses
vtsls (Zed, built-in) / `typescript-language-server` (Helix); Biome formats +
organizes imports; nixd + alejandra handle Nix. Zed auto-installs the Biome + Nix
extensions.

## Git hooks (devenv git-hooks)

- **pre-push:** biome, tsc, eslint, jest — run from `node_modules/.bin` (the
  pinned devDependencies, the single source of truth) — plus builtins (typos,
  markdownlint, lychee, gitleaks `protect`, Nix alejandra/deadnix/statix).
- **manual:** `expo-doctor`, `security-scan` —
  `pre-commit run --hook-stage manual <id>`.
- Commits to `trunk` are blocked; branch first. `pre-commit run --all-files`
  runs the push-stage hooks on demand.

## Gotchas

- Commands only exist in the devenv shell. "command not found" → you're outside
  it.
- Run Jest via `bun run test` (Node). Do **not** run `bunx --bun jest` — Bun's
  runtime breaks jest-runtime ("Attempted to assign to readonly property"). tsc
  and eslint are fine under bun; only jest must use Node.
- If a `devenv update` breaks the eval with a git-hooks assertion:
  `devenv inputs add git-hooks github:cachix/git-hooks.nix --follows nixpkgs`,
  and confirm `devenv.yaml` still has `allowUnfree: true`.
- Dependencies are two-track (no wildcards): `expo install` for Expo-governed
  packages, caret + `bun update` for free tooling. See `CONTRIBUTING.md` and the
  `upgrade-expo-sdk` skill.
